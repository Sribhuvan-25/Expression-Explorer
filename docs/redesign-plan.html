Implementation plan — revised, not yet built

UI Redesign — Workspace Model

Revised after feedback: a reskin wasn't enough. This replaces the page-per-analysis structure with an IDE-style workspace — resizable, splittable panes, a command bar as the fast way in, query controls that stay visible (never auto-collapsed), and purposeful motion. Palette/type direction from the first pass carries over unchanged: Clinical — navy, cobalt, sharp corners, Space Grotesk.

01 What's actually changing

The previous plan kept the existing five-page structure (Compare, Signature, Rank, Survival, Genome Tracks as separate routes) and only changed colors/fonts. That's a reskin, not a redesign. The real gap: each analysis lives in isolation — run a comparison, want to also see survival for the same gene, and you navigate away and lose the first result entirely.

The core change

Analyses become panes in one workspace, not pages. A pane is a live instance of one analysis — its own query controls plus its own result — and panes can be split, resized, and arranged side by side. Run a comparison in one pane, split right, run survival on the same gene in the new pane, look at both at once. This is genuinely how a research tool should feel in this era — closer to an IDE or a notebook than a five-tab SaaS dashboard.

02 Workspace layout

Built on dockview — a zero-dependency React docking layout library (tabs, groups, resizable grid splits, drag-to-rearrange) already used for exactly this kind of IDE-style interface. Not building a pane manager from scratch; that's a solved problem and reinventing it would be the wrong use of effort here.

What a pane is, concretely

  • Each pane wraps one existing page component (ComparePage, SurvivalPage, etc.) — the analysis logic and API calls don't change, only how they're framed and arranged on screen.
  • Query controls render inside the pane, always visible — this was explicit feedback: don't collapse controls away once a result exists. Density comes from a more compact control strip, not from hiding anything.
  • Panes are addressable — dockview tracks layout state, which can be serialized so a workspace arrangement survives a refresh (stretch goal, not required for v1).
  • Genome Tracks is a special case: igv.js instances are heavy (remote bigWig streaming) and don't tolerate being resized/remounted casually. It gets its own pane type that defers/guards against layout thrashing rather than behaving like the lightweight chart panes.

03 Command bar

The fast way in — ⌘K / Ctrl+K opens a command palette. Typing a gene symbol jumps straight toward results; typing an analysis name opens that pane type. Forms still exist inside each pane for full control — the command bar is a faster front door, not a replacement for the controls.

  • Gene-first: type MYCN → suggested actions: "Compare MYCN", "Signature score with MYCN", "Rank by MYCN" — pick one, a new pane opens pre-filled and already querying.
  • Action-first: type survival → opens a blank Survival pane focused on its gene-set input.
  • Split-aware: holding a modifier (or a trailing flag like "split right") opens the result into a new pane beside the current one instead of replacing it — matches the mock above.
  • Built on a lightweight fuzzy-match list, not a new dependency-heavy command-palette library — the surface area here is small (5 analysis types × known genes/presets).

04 Motion

Purposeful and restrained — motion that clarifies a state change, never decoration.

  • Chart entrance: box plots and survival curves draw in (stroke-dasharray reveal or a quick fade+rise), so a new result reads as "this just arrived" rather than popping in instantly.
  • Pane operations: dockview's own split/resize/drag transitions, tuned to feel quick (150–200ms) rather than showy.
  • Loading → loaded: the current abrupt swap (spinner → full result) gets a brief crossfade so the layout doesn't jump.
  • Explicitly not doing: number count-ups, decorative background motion, anything that would make a hard chart-reading task feel gimmicky. This is a research tool.
  • prefers-reduced-motion respected throughout — instant transitions when set.

08 Responsiveness

Desktop through tablet, ~900px and up — unchanged target from the first pass. The workspace model makes this more important, not less: a pane grid needs a sane collapse behavior on a narrower screen.

  • ≥1024px: full dockview grid, multiple panes side by side as shown in the mock.
  • 900–1024px: dockview's grid degrades to a single-column stack of tabs rather than forcing panes to shrink past usability — still splittable, just defaults to less side-by-side.
  • <900px: out of scope, flagged not silently broken, same as before.
  • Genome Tracks pane keeps its own min-width guard regardless of breakpoint.

09 Downloadable figures (unchanged from first pass)

PNG export with stats baked in, via the existing hand-built SVG charts → canvas → blob path. No new dependency. Export button lives in each pane's chart header.

10 Build order

This is bigger than the first plan — the pane system is foundational and everything else sits on top of it. Sequenced so each phase is independently useful, not one big-bang rewrite.

1

Tokens + fonts

Same as before — palette and font swap first, fastest way to confirm the visual direction before any structural work.

2

Dockview shell

Install dockview, replace the react-router page structure with a single workspace route hosting a dockview grid. Wrap each existing page component as a pane content renderer — no analysis logic changes, just how it's mounted. One default pane open on load (Compare), matching today's "land on Compare" behavior.

3

Multi-pane operations

Split/open-new-pane actions wired up (a "+" affordance and/or right-click → split), Genome Tracks' special-case guard, layout persistence to localStorage so a refresh doesn't lose the arrangement.

4

Command bar

⌘K palette, gene-first and action-first entry, wired to open/split panes.

5

Motion + shell polish

Chart entrance animation, loading→loaded crossfade, sharp-corner primitives, Sources disclosure, drop the version subtitle.

6

Figure export + responsive pass

PNG export hook, tablet breakpoint behavior for the dockview grid.

Honest sizing

Phases 2–3 (the actual workspace rebuild) are the majority of the effort here — genuinely a different application shell, not a styling pass. Phases 1 and 5 are comparatively fast. Worth building and checking in after phase 2 lands before continuing, rather than committing to the full sequence blind.

Nothing in this plan has been implemented yet — revised scope for review before code changes begin.
