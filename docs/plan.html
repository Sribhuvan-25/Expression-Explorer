Project scope & build plan

ETP-ALL Expression Explorer

A TNMplot-style analysis tool, built first to answer the MYCN and PP2A questions raised in the margins of the Wang et al. ETP-ALL manuscript — and designed so the next dataset and the next disease area drop in without a rewrite.

01 What you're actually asking for

Two things, and they pull in different directions — which is worth naming up front because it shapes every decision below.

  • Immediate: answer six specific questions your collaborator wrote into the PDF margins. These are concrete, dataset-bound, and finishable.
  • Structural: don't answer them with throwaway scripts. Build the thing that answers them and the next set, across datasets and disease areas you haven't chosen yet.

The risk in a project shaped like this is building the general platform first and never getting to the biology. The plan below inverts that: ship the answers through a thin slice of the real architecture, so the platform is proven by use rather than designed in advance.

The unifying pattern

Every request is the same operation with the gene set swapped: take the paper's ETP-TF5 / ZMIZ1-5 machinery and re-run it on a MYCN/PP2A gene set. That is a strong signal for the architecture — the gene signature must be a first-class user input, not hardcoded. Build that one abstraction and five of the six comments are the same feature.

Open question for you

There is no canonical "PP2A signature" — it could mean the subunit genes (PPP2CA, PPP2R1A, the B-subunit family), the endogenous inhibitors (SET, CIP2A, PPME1), or a published activity signature. This changes every result. I'd default to a curated list you can edit in the UI, but the definition should come from Sathish.

03 What TNMplot does, and where we differ

TNMplot v2 aggregates ~57,000 samples across GEO, GTEx, TCGA and TARGET, and offers pan-cancer boxplots and dot matrices, tumour–normal–metastasis comparisons, correlation analysis, stage comparison, and GO/KEGG enrichment. Statistics are Mann–Whitney with Pearson/Spearman correlation. It's a strong functional model.

Three things it doesn't do that this project needs:

  • Survival is absent. TNMplot is expression-only — Kaplan–Meier lives in the sibling tool KMplot. Half the margin comments are survival questions, so we need it in the same surface.
  • Signature scoring is limited. The paper's method is AUCell rank-based scoring, not a mean of log values. That's the machinery the comments implicitly ask to reuse.
  • Subtype grouping is fixed. We need arbitrary sample groupings — AALL0434 subtype, ETP status, MRD status — as a user-selectable axis.

On the UI: TNMplot is functional but dated — dense forms, small controls, results that arrive as static images. The bar for "better and more intuitive" is genuinely reachable. The plan is a persistent left control rail, a results canvas that updates without a full page reload, real hover tooltips on every plot, and every figure exporting to publication-ready SVG with its statistics attached.

05 Architecture — adaptive by construction

"Adaptive" fails when it means a config file bolted onto hardcoded assumptions. The way it holds is a strict contract: every dataset, whatever the disease or assay, is normalised at ingest into the same three objects. Analysis code only ever sees those objects and never knows which dataset it's looking at.

ContractExpression matrix · sample metadata · feature metadata. Plus an assay-type tag, so the tool knows qPCR can't answer a genome-wide question.
IngestOne loader per source — GDC, GEO, DepMap. Loaders are the only place source-specific logic is allowed to live.
StoreParquet on disk, cached. Fast enough for the current scale; swappable later without touching analysis code.
AnalysisPure functions over the contract — group comparison, signature scoring, survival, correlation. Testable in isolation.
APITyped endpoints. Keeps heavy compute off the browser and lets analyses be scripted, not just clicked.
UIControl rail plus results canvas. Every view is a URL, so any result is shareable and reproducible.

The two decisions that buy the most adaptability:

  • Gene sets are user data, not code. Named, saved, editable, shareable. ETP-TF5 and MYCN/PP2A ship as presets, but they're just rows in the same table a user creates.
  • Sample grouping is a declared column, not a hardcoded axis. "ETP vs near-ETP vs non-ETP", "MRD±", "subtype" and any future clinical variable are all the same operation. A new disease area contributes new grouping columns and needs no new analysis code.
Proposed stack, and why

Python / FastAPI backend. Non-negotiable in practice — the paper's methods are AUCell, survival, and Seurat. The scientific libraries you need bindings to are here, and matching the published method matters more than language preference.

React + TypeScript frontend with a typed client generated from the API schema, so the two halves can't silently drift.

Plot layer: Vega-Lite or Observable Plot over D3-by-hand. Both emit clean SVG for figures, which is the actual deliverable for a manuscript.

Survival: R's survival via a thin bridge, or lifelines in pure Python. The paper used R's survfit, so the bridge reproduces published numbers more defensibly.

AUCell has no Python equivalent that matches exactly. Either bridge to R or reimplement the rank-based AUC — it's a tractable algorithm, and reimplementing means validating against the paper's published figures. That validation is worth doing regardless.

06 Build sequence

Ordered so that something real is testable early, and each phase exercises the architecture rather than deferring it. Phases 1–3 answer four of the six comments.

P1

Data spine

GDC and DepMap loaders, the three-object contract, Parquet cache. Harmonise gene identifiers to Ensembl with symbol aliasing — silent identifier mismatch is the most common way analyses like this go quietly wrong.

Ships: TARGET + DepMap queryable from a notebook. No UI yet.

P2

Expression comparison

Group comparison with boxplots and violins, Mann–Whitney and Kruskal–Wallis, FDR correction. Grouping driven by any metadata column.

Answers: comment 1 — MYCN/PP2A across TARGET by ETP status.

P3

Signatures & survival

Signature scoring (AUCell-equivalent, validated against the paper's ETP-TF5 figures), score binarization, Kaplan–Meier, Cox proportional hazards with covariates.

Answers: comments 3 and 4 — PP2A survival, subtype boxplots. Rebuilds Fig. 10.

P4

Cell-line explorer

Ranked, filterable table across DepMap and the GEO lines — sort by gene or signature score, filter to leukemia lineage, flag high/low candidates with the evidence attached.

Answers: comment 2 — the cell-line purchasing decision.

P5

Interface

Control rail, results canvas, URL-encoded state, SVG/PNG/CSV export with statistics attached. This is where the "neat and intuitive" bar gets met — and it comes after the science works, not before.

Ships: a tool Sathish can drive without you.

P6

Extension

Correlation and correlation profiles, GO/KEGG enrichment, pan-dataset dot matrix. Second disease area added as the real test of whether the abstraction held.

Proves: the adaptivity claim.

07 Risks worth knowing now

  • Batch effects across sources. TARGET, DepMap and GEO were processed differently; cross-dataset comparison of absolute expression is not valid without correction. Mitigation: default to within-dataset comparison, and mark any cross-dataset view explicitly as exploratory.
  • The PP2A signature is undefined. Flagged above — it gates real analysis and is a question, not a task.
  • AALL0434 is not public — confirmed. Phase 3's subtype boxplots depend on it, and no amount of engineering solves it. Either Sathish supplies the matrix through the collaboration, or that one request goes unanswered while everything else proceeds on TARGET. Resolve in parallel with Phase 1 rather than waiting.
  • AUCell reimplementation may not match exactly. Mitigation is built into Phase 3: validate against the paper's published ETP-TF5 figures before trusting it on new gene sets. If the numbers reproduce, the method is sound.
  • Signature scoring on small gene sets is unstable. A five-gene signature behaves differently from a fifty-gene one. Rank-based scoring needs a documented minimum, and the UI should warn below it.
